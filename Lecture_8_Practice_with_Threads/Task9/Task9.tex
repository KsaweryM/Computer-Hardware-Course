While we are at it, I'd like to point you to one more tool that you will meet quite often in our code base:
\textbf{semaphores}. Here is a short summary, so that we have the same context.

\textbf{What a semaphore is.} It is a counter that can never go below zero. It has two operations:
\begin{itemize}
  \item \texttt{acquire()}: if the counter is greater than zero, decrease it by 1 and return at once.
        If the counter is 0, the thread sleeps until somebody increases it.
  \item \texttt{release()}: increase the counter by 1 and wake up one of the waiting threads.
\end{itemize}

Fun fact: semaphores were invented by Dijkstra, the same person who described producer-consumer, and in the same
work from 1965 he solved that problem with them.

\textbf{How to use it in C++.} Since C++20 there is \texttt{std::counting\_semaphore<N>} in the header
\texttt{<semaphore>}. An example from our own backyard: the GPU has 3 hardware decoding units, so at most 3 streams
can be decoded at the same time.

\begin{code}
std::counting_semaphore<3> hw_decoders{3};   // 3 free units at the start

void decode_stream(int id) {
    hw_decoders.acquire();    // take a unit; if all are taken, sleep
    decode(id);
    hw_decoders.release();    // give the unit back
}
\end{code}

\textbf{How it differs from a mutex.} A mutex is in practice a semaphore with a counter of 1, with one important
difference: only the thread that locked a mutex may unlock it. \texttt{release()} of a semaphore may be called by
\textbf{any} thread. That is why a semaphore is good not only for limits but also for signalling: one thread calls
\texttt{release()}, another one waits in \texttt{acquire()}.

\textbf{When a semaphore, and when a condition variable.} If you wait for a simple count (``there are free places'',
``there is something to do''), a semaphore usually gives shorter code. If the condition is more complex, stay with
a condition variable.
